# 咖啡萃取簡報：loop / graph 設計說明

## 流程圖（graph）
```
[取得來源] ──→ [查 Wiki] ──→ [整理重點] ──→ [檢查數字] ──→ [產生簡報]
     ▲             │              ▲               │
     │             │              │   不通過      │
     └─────────────┘              └───────────────┘
   （來源不足或來源有問題）       （數字與來源不符）
```

## 各節點
| 節點 | 做什麼 | 輸入 | 輸出 |
|---|---|---|---|
| 取得來源 | 找網路來源，依層級分類（一手、次級、三級） | 主題關鍵字 | `raw/` 中的來源檔 |
| 查 Wiki | 讀 `index.md`，找出相關概念頁 | 主題問題 | 相關 wiki 頁面清單 |
| 整理重點 | 把來源內容改寫成自己的概念頁，數字寫入數字表 | 來源 + wiki 頁 | `wiki/` 概念頁與 `數字表.md` |
| 檢查數字 | 逐一比對簡報將用的數字與數字表，檢查衝突與待核對標記 | 數字表 + 簡報草稿 | 通過 / 不通過清單 |
| 產生簡報 | 依通過的內容產生 HTML 投影片 | 通過的概念頁 | `coffee-slides/index.html` |

## 哪些步驟會重複
- **取得來源 ↔ 查 Wiki**：若查 Wiki 時發現某概念沒有可靠來源，回到取得來源補資料。
- **整理重點 ↔ 檢查數字**：數字不通過時，回到整理重點修改頁面。
- **檢查數字 → 產生簡報**：只有通過檢查的內容才能進入簡報正文。

## 哪裡需要檢查或重新生成
1. **檢查數字**是最重要的閘門。衝突或待核對的數字不得直接輸出到簡報正文，只能並列呈現。
2. 每次修改 wiki 頁面後，都要重新檢查數字表。
3. 簡報產生後，要再次核對每張投影片的數字是否與數字表一致。

## 為什麼這樣設計
- 數字是這個主題最容易出錯的地方（同一數字在不同來源有不同值）。把數字檢查放在產生簡報之前，可以避免錯誤直接進入成品。
- 把 wiki 當成中間層，可以讓簡報只依賴已整理過的內容，而不是直接拼湊網路原文。
- 來源分級與衝突並列，讓簡報能說明「數字為什麼不同」，而不是只給一個答案。
